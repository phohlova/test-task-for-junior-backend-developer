# Task Service — Медицинский трекер задач с периодичностью

Модуль трекера задач для медицинской информационной системы. Позволяет врачам создавать задачи и настраивать их периодическое повторение.

##  Функциональность

### Базовый CRUD
- Создание, просмотр, редактирование и удаление задач
- Фильтрация по статусу

### Периодические задачи (новая функция)
Поддержка 4 типов периодичности:

| Тип | Описание | Параметры |
|-----|----------|-----------|
| `daily` | Каждый n-й день | `interval` (≥1) |
| `monthly` | На конкретное число месяца | `day_of_month` (1–31), `overflow_strategy` |
| `specific_dates` | На указанные даты | `specific_dates` (массив дат) |
| `parity` | По чётным / нечётным дням | `parity_mode` (`even` / `odd`) |

### Фоновый воркер
- Автоматическая генерация экземпляров задач по расписанию
- Идемпотентная вставка (защита от дубликатов при перезапуске)
- Шардирование для масштабирования

##  Архитектура

Проект следует принципам **Clean Architecture**:

cmd/api/ — точка входа
internal/
domain/task/ — доменные сущности и бизнес-правила
usecase/task/ — сценарии использования
repository/postgres/ — реализация доступа к данным
scheduler/ — фоновый воркер генерации
transport/http/ — HTTP-обработчики и DTO
infrastructure/ — подключение к БД
migrations/ — SQL-миграции


### Ключевые паттерны
- **Strategy** — для генераторов дат (OCP)
- **Specification** — для валидации конфигурации
- **Dependency Injection** — явная передача зависимостей через конструкторы

### Хранение периодичности
Гибридный подход: **JSONB + Generated Columns** в PostgreSQL:
- `recurring_config JSONB` — гибкое хранение настроек
- `rec_type`, `rec_day_of_month` — материализованные колонки для индексации
- `CHECK`-констрейнты — валидация на уровне БД

##  Запуск

### Требования
- Docker
- Docker Compose

### Запуск
```bash
docker compose up --build
```
Приложение будет доступно на http://localhost:8080.

### Остановка
```bash
docker compose down
```

Основные маршруты:
- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`

## Тестирование
В репозитории есть готовая коллекция Postman (tests-medtasks.json) для тестирования всех эндпоинтов и граничных случаев.

## Принятые допущения
- Даты в UTC: все даты хранятся в UTC, таймзона пользователя учитывается при генерации

- 31-е число в коротком месяце: при overflow_strategy=skip — пропускается, при last_day — переносится на последний день

- 29 февраля: задача создаётся только в високосные годы

- Изменение периодичности: новые правила применяются только к будущим экземплярам

- Генерация экземпляров: воркер создаёт задачи на 24 часа вперёд

- StartDate в прошлом: система вычисляет ближайшую валидную дату ≥ now
